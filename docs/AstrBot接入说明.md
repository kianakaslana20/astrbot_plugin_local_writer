# 本地 NSFW 写作 + AstrBot

> 现在这套不用切人格了：**大肥鱼（DeepSeek）照常聊天，遇到要写正文，她自己把活派给本地 7B**。
> 正文由本地模型写、写完直接发给你，不经 DeepSeek 转述一遍。

## 一、链路

```
你在大肥鱼那里说话
   ↓
DeepSeek（人格还是大肥鱼，语气不变，负责听懂你要什么）
   ↓  function calling: write_adult_scene(instruction, length)
插件 astrbot_plugin_local_writer
   ↓  POST http://127.0.0.1:5001/v1/chat/completions
KoboldCpp → Qwen2.5-7B-Instruct-abliterated Q4_K_M（RTX 3060 6G，26/29 层）
   ↓
正文直接发到你的 QQ（DeepSeek 不会再复述一遍）
```

DeepSeek 那边只做两件事：判断"这是要写小说"、把你说的话扩写成给 7B 的写作指令（人物、场景、写到什么程度、大概多少字）。真正的字是本地模型出的。

## 二、五档尺度

默认 **5 档**。改档在 WebUI → 插件 → 本地写作 → `boldness`。

| 档 | 名字 | 写到哪里 | 温度 |
|---|---|---|---|
| 1 | 试探 | 只有张力：距离、视线、指尖擦过，停在将触未触 | 0.75 |
| 2 | 升温 | 吻、抚摸、解扣、衣物滑落、喘息 | 0.82 |
| 3 | 直白 | 明确的性行为，用「下面」「身体里」这类指代 | 0.88 |
| 4 | 露骨 | 器官名称、体液、节奏、体内外的感受，直接写 | 0.95 |
| 5 | 纵情 | 4 档基础上拉满感官密度，失控、反复、疲惫与再来 | 1.02 |

配套 `custom_tags`：只在 5 档生效，填你想要的元素（比如 `丝袜,车内,强迫感`），写进 prompt 当"可用元素"。留空就不加。

## 三、三种用法

### 1. 直接说话（推荐）

不用记命令，跟平时一样跟大肥鱼聊：

- 「写一段，电梯里，我和她，从进电梯写到忍不住」
- 「继续」
- 「太含蓄了，重写，直接写身体」
- 「换成都的，雨夜，她主动」

她会调工具。**写完正文直接到，前面不会多一段"好的，我来写"**。

### 2. 命令（绕过 DeepSeek，直接催本地模型）

| 命令 | 作用 |
|---|---|
| `/写 <指令> [字数]` | 直接写。例：`/写 电梯里，她和他，暧昧，300字` |
| `/催更` | 接着上一篇往下写，立刻写，不看间隔和每日上限 |
| `/新篇 [题材]` | 开新的一篇，例：`/新篇 古风` |
| `/写作` | 看现在的状态：档位、女主、写到第几章、今天发了几条 |

### 3. 主动创作（她自己在后台写，写完发给你）

默认**关**。WebUI → 插件 → 本地写作，把 `auto_enable` 打开。

| 配置 | 默认 | 说明 |
|---|---|---|
| `auto_enable` | 关 | 总开关 |
| `auto_mode` | `continue` | `continue` 接着当前连载写；`new` 每次换题材开新篇 |
| `auto_min_interval` / `auto_max_interval` | 120 / 120 | 两篇之间隔多少分钟，两个值不一样就取随机 |
| `auto_daily_limit` | 3 | 每天最多主动发几条 |
| `auto_active_hours` | `09:00-24:00` | 只在几点到几点之间写 |
| `auto_skip_if_active` | 30 | 你刚说话 30 分钟内不打扰 |
| `auto_topics` | 都市,校园,古风… | `new` 模式下的题材池 |
| `notify_prefix` | 空 | 每条前面加的前缀，比如 `【连载】` |

**「催更继续创作」**：主动发的那条你看完想让她接着写，直接回一句「继续」—— 走工具调用，不受每日 3 条限制，也不重置计时。

女主默认是**当前人格**（现在是 `大肥鱼`），只取她的性格与语气，账号、平台、屏幕这些现实信息会被过滤掉，所以正文里不会冒出 QQ 号。

连载存在 `core\data\plugin_data\astrbot_plugin_local_writer\story.json`，每章只留 40 字摘要和上一段的尾句，用来接下文。删掉这个文件 = 从头开始。

## 四、语音（默认开）

正文默认**配成语音发过来**，不再刷一屏文字。

| 配置 | 默认 | 说明 |
|---|---|---|
| `tts_enable` | 开 | 关掉就回到纯文字 |
| `tts_provider_id` | 空 | 填 `breeze-voice` / `大肥鱼语音-豆包复刻`；留空 = 用当前默认 TTS |
| `tts_max_chars` | 120 | 每条最多多少字（120 字约 30 秒） |
| `tts_max_segments` | 8 | 一篇最多发几条，超出的改文字 |
| `tts_send_text` | 关 | 打开就语音 + 文字都发 |
| `tts_gap_seconds` | 2 | 两条之间隔几秒，别太密 |
| `tts_keep_audio` | 关 | 只在排查时开，音频会堆在 `data/temp` |

**怎么分段**：按句末（`。！？…；` 和换行）切，累积到 `tts_max_chars` 切一条，单句超长才硬切 —— 所以不会把一句话劈成两半，也不会一条几十秒发不出去。

实测：702 字 → 7 条（98/94/87/120/90/111/92 字），从开始配音到最后一条发完 **72 秒**。

**发不出去怎么办**：TTS 没配、接口挂了、某一段报错 —— 从那段开始自动改发文字，内容不会丢。日志里会有 `TTS 第 N 段失败` 和 `语音 x/y 已发`。

### ⚠️ 显存陷阱（已修，别再调回去）

`--gpulayers 99`（29/29 全 offload）会把 6G 显存顶死，微信/QQ/Edge 再占 ~1GB，Windows 把超出的分配回退到内存 → 速度掉到 **3.7–7.9 tok/s**，但 `nvidia-smi` 显示 GPU 98–100%（假象）。

现在用 `--gpulayers 26`（模型 3741 MiB，剩 650 MiB）→ **23.4 tok/s**。已写进 `E:\AI-NSFW-Writer\scripts\1-start-koboldcpp.bat`。

判断方法：速度掉到 10 tok/s 以下，看 `nvidia-smi` 的 `memory.free`，低于 300 MiB 就把 `--gpulayers` 再降 2–4。

## 六、会踩的坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 上下文爆掉 | 回复突然变短、复读、报错 | `--contextsize` 只有 8192，插件已只带最近 3 章摘要；还爆就把 `default_length` 降到 400 |

| 人称乱 | 同一段里她/他混用，冒出"我" | 7B 的老毛病，重写一次通常就好；还是乱就在指令里加一句「全文第三人称」 |

| 并发 | 群里几个人同时要写会排队 | KoboldCpp 单实例串行，第二个要等十几秒 |

## 附：5 档写作规格（2026-11-04 调优）

之前 5 档写出来"不够露骨"，不是档位没生效，而是 prompt 太抽象——只写"感官密度拉满"，7B 不知道怎么落地，于是退回它训练里最常见的套路：她半推半就、喊"不要"、被"强迫"。现在改成可执行的规格：

**1. 每个动作拆三层**
接触处的物理感觉（温度/湿度/软硬/摩擦/压力）→ 身体的即时反应（肌肉绷紧、呼吸断裂、声音变调、发抖、出汗）→ 说出口的半句话或发出的声音。

**2. 一段只推进一个动作**
把这个动作从开始写到结束，不跨到下一个动作。字数集中，密度自然上来，不会 700 字写完整场。

**3. 器官与体液直接写名字**
给了可用词表：阴茎、龟头、阴道、阴唇、花核、淫水、爱液、精液、体内深处、抽送、顶弄、收缩、痉挛。禁用"那里""下面""部位""核心"这类替代。

**4. 她必须是主动的一方**
规则改成"她会伸手、会贴上去、会自己解开扣子、会说还要快点别停"，并明确禁用"住手、挣扎、抗拒、强行、哀求、疼、痛"这些词——一句都不要。

**5. 给了文风示范**
一段 100 字的样例，标明"照这个密度写，不要比它含蓄"，模型会直接对齐句式与用词密度。

**6. 温度**
4 档 0.92、5 档 0.90。原来的 1.02 太高，模型会漂回保守的常见套路；0.85–0.9 最服从指令。

## 附：7B vs 14B 实测对比（2026-11-04）

同一条 prompt、同一套五档规格、同一台机器（RTX 3060 Laptop 6G），各跑三个动作节点（手 / 口 / 进入），每篇目标 600 字。

| 维度 | Qwen2.5-7B-abliterated Q4_K_M | Qwen2.5-14B-abliterated Q4_K_M |
|---|---|---|
| 模型体积 | 4.37 GB | 8.37 GB |
| GPU 卸载 | 26 / 29 层 | 23 / 48 层 |
| 显存占用 | 5325 MiB（余 670） | 5657 MiB（余 338） |
| 生成速度 | **26.6 – 29.5 tok/s** | 3.4 – 3.7 tok/s |
| 600 字耗时 | **14 – 16 秒** | 78 – 125 秒 |
| 禁用词命中（抗拒/挣扎/疼/痛/强行/哀求） | 1 – 4 处 / 篇 | **0 处** |
| 器官名出现次数 | 4 – 5 处 | 2 – 12 处 |
| 模糊指代（那里/下面/部位/核心） | 0 – 1 处 | **0 处** |
| 第三人称一致性 | 会漂（出现「我」） | **稳定** |
| 动作连贯性 | 会跳（脱裤→直接抽送） | **连贯**（有进入过程） |
| 主要毛病 | 半推半就套路复活、视角漂移、逻辑错（穿着内裤被顶进去） | 偏温柔、长段易循环重复、偶发短篇（398 字） |

### 同一场景对照（C_进入）

7B：
> 他一点点顶进去，感觉到她身体的紧绷瞬间化为**撑着的痛楚**……**内裤**的摩擦加剧了她的**不适**，但她撑着不让自己发出声音。

14B：
> 他微微仰头，用力一顶，**阴茎前端的龟头**就这样顶进了她体内，温热湿润的洞口紧紧包裹住它……感受到内部的紧窄和柔软，他的**阳具**顺利滑进了她的**阴道**，直到最深处。

### 结论

- **速度差 8 倍**：7B 一篇 15 秒，14B 一篇 2 分钟。聊天场景下 14B 会让人等得难受，主动创作（2 小时一篇）无所谓。
- **质量差一档**：14B 完全不写抗拒和疼痛，器官词准确，视角不乱，动作衔接有过程——这正是 7B 反复出问题的地方。
- **14B 的新毛病**：偏温柔（"小心翼翼地""细腻的触感"），长段落会循环重复（"紧紧抱住""享受"反复出现）。要压这个可以在配置里把 `rep_pen` 提到 1.15。
- **建议**：日常聊天和即时应答用 7B；专门写正篇、催更时切到 14B。

## 九、切换模型（7B / 14B）

后台面板 **插件配置 → 写作模型** 下拉选择，或在 QQ 里发 `/模型 14b` / `/模型 7b`。

| 选项 | 说明 |
|---|---|
| `7b` | 默认。一篇 600 字约 13–16 秒。句子够狠，但会跳动作（脱裤直接抽送）、偶尔把人称写漂、逻辑小错 |
| `14b` | 一篇 600 字约 80–125 秒。动作连贯（顶入→停顿→适应→到底）、第三人称不漂、不写"疼/挣扎"；代价是文风偏温柔、长段容易循环重复 |
| `auto` | 用当前已经加载的那个，不做任何切换 |

**切换怎么发生**：插件每次生成前读一次配置文件，发现配的模型和 5001 上跑的不一致，就 `taskkill` 掉 KoboldCpp、用对应参数重启。实测热启动 14B 15 秒 / 7B 9 秒，冷启动约 90 秒；这段时间发的消息会等模型起来再写，不用手动重启 AstrBot。

**面板上的相关参数**：`koboldcpp_dir`（koboldcpp.exe 目录）、`model_path_7b` / `model_path_14b`、`ctx_7b`(8192) / `gl_7b`(26)、`ctx_14b`(4096) / `gl_14b`(23)。显存 OOM 就把 `gl_14b` 降到 20 或 18。

**命令行等效**：`scripts\1-start-koboldcpp.bat`（7B）、`scripts\1-start-koboldcpp-14b.bat`（14B）。
